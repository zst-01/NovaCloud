# 登录、退出与会话鉴权

## 已授权的阶段与设计

沿用四个 Java 进程和两层网关。MySQL 保存演示账号及 BCrypt 密码哈希；中台完成密码校验，生成 32 字节安全随机 token（64 位十六进制）。Redis 保存 `lab:session:<token>`，固定 30 分钟 TTL，不自动续期。客户端使用 Authorization: Bearer token。

应用层负责转发登录、当前用户、退出请求及 Authorization。两层网关通过响应式 Redis 客户端校验会话；中台再次检查会话，避免直接访问服务绕过保护。请求携带的用户身份头不作为授权依据。工单查询要求 ticket:read 权限。

鉴权采用默认校验：只精确放行 POST 登录及所需健康检查路径，其余请求先检查会话。除个人信息和退出接口外，当前其余业务路径均要求 ticket:read。未知路径在已授权后仍返回 404；编码路径、矩阵参数或健康检查路径前缀不能变成免鉴权入口。

- POST /api/auth/login：用户名密码换取 token；只有这个认证接口允许匿名访问。
- GET /api/auth/me：返回当前用户及权限，不返回密码或会话 token。
- POST /api/auth/logout：删除当前会话；再次使用该 token 返回 401。
- GET /api/tickets/{id}：必须有有效会话和 ticket:read 权限。
- 无效/缺失/过期 token 为 401，无权限为 403，Redis 故障为 503，故障时不放行。

演示账号 demo 有查询权限，observer 无查询权限；本地 .env 随机生成 DEMO_PASSWORD，两个演示账号初始使用此密码，MySQL 中只存各自的 BCrypt 哈希。首次启动增加独立 lab_users 表并仅补充缺失账号，不删除已有数据，不重置已有密码。

## 实施与验收顺序

1. 编写网关拒绝、权限判断、Redis 故障测试及会话生命周期测试，确认未实现时失败。
2. 增加中台账号初始化、登录会话、服务保护，以及应用层转发和两层网关检查。
3. 配置网关 Redis、演示凭据和路由；调整已有链路/TraceId/故障验证脚本，在登录后验证原业务行为。
4. 全量 Java 测试、构建并部署镜像；验证错误密码、无 token、伪造身份、权限不足、正常查询、退出、TTL 过期及各层直接访问保护。
5. 验证 Redis 停机时拒绝访问并恢复服务；更新 README、学习文档和搭建日志。

## 验收记录

本阶段已于 2026-09-06 实测完成：46 个 Java 测试通过，完整启动验收成功，登录/权限/过期/退出/直接访问保护及 Redis 停机拒绝通过。中台网关故障实验恢复成功，最终 8 个容器健康。过程、失败原因及修复见根目录搭建日志.md。

## 范围说明

这是本机学习环境的账号会话和接口权限示例。没有注册、密码修改、完整 RBAC 后台、SSO、刷新 token、登录限流或 HTTPS；不作为公网部署方案。Kafka 留待后续。会话中权限是登录时快照，修改数据库权限后应退出重登；完整账户禁用及强制全端退出尚未实现。
