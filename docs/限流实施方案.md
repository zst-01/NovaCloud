# 登录与接口限流

本次按用户授权仅实现登录和工单接口限流，Kafka 不在范围内。

## 设计

- 应用网关新增 GlobalFilter，在鉴权通过、路由匹配后执行；登录路由匿名，但仍受来源额度限制。中台网关不重复扣额度。
- 将应用网关路由拆成 login、tickets、其余 auth。按实际匹配路由选择策略，避免编码路径或矩阵参数绕过限流。
- 默认登录同一来源 IP 30 秒 10 次，计入成功及失败尝试；工单接口同一已验证用户名 10 秒 20 次。当前用户名是数据库主键，多个 token 共用额度。
- Nginx 覆盖 X-Lab-Client-IP 为实际连接来源，不采信客户端填写值。应用网关只在受信任的 Docker 内网接受此入口头，缺少时使用直连地址。网关不发布宿主机端口；此设计不承诺防御已能伪造内网流量的容器，若引入其他入口应重新配置代理信任边界。
- Redis 固定窗口从首次请求开始，Lua 原子完成读计数、检查、增加及过期设置。拒绝不延长窗口；额度、剩余 TTL 来自同次脚本执行。登录与用户使用独立 key 前缀，身份经 SHA256 后组成 key，不保存 token。
- 返回 429 / rate_limited，Retry-After 为剩余窗口向上取整的秒数；Redis 故障返回 503 / rate_limit_unavailable，不能放行。其他业务错误保持原响应。
- 默认只对鉴权与权限通过的工单请求计数；匿名或无权限请求保持 401 / 403。个人信息、退出和健康检查不消耗额度。

## 实施和验收

1. 在现有环境运行超额登录验收，确认尚无 429。
2. 编写 Redis Lua 并发/共享额度/窗口恢复集成测试，网关测试覆盖 429、503、路由和已验证身份。
3. 实现过滤器、配置和 Nginx 来源头；原验收脚本登录遇到限流时按 Retry-After 等待，以免清空真实计数。
4. 构建并部署应用网关，跑完整启动验收；实际 HTTP 检查伪造头、多个 token 共用额度、超限和恢复、429 日志。
5. 更新搭建日志、README 和学习文档。测试不执行 FLUSHDB，不删除普通用户的计数或会话。

固定窗口允许窗口交界处短时突发，不等于平滑流量整形；来源 IP 会受 NAT、Docker Desktop 转发影响，同一来源的用户可能共用登录额度。阈值是学习默认值，不是生产容量结论。

## 实际验收（2026-09-07）

已完成全部步骤：54 个 Java 测试通过，包含真实 Redis 并发共享额度及过期恢复。完整启动验收成功；HTTP 登录额度、同用户多 token 额度、伪造头与特殊路径、429 日志以及 Redis 故障 503 均已验证。故障恢复后 8 个容器健康，原 19 项链路检查通过。详见根目录搭建日志.md。
