# 浏览器工单工作台

打开 [工作台](http://127.0.0.1:18080/)，在左侧登录后查询工单。

## 第一次操作

1. 使用账号 demo，密码从项目本地 .env 的 DEMO_PASSWORD 取值，不包含前面的键名和等号。
2. 点击“登录工作台”，页面显示当前用户及权限。
3. 查询编号 1，得到 MySQL 中的演示工单；查询 999999，体验不存在的提示。
4. 查看底部 HTTP 状态、耗时和 TraceId，可以复制编号后用 show-trace.ps1 查后台日志。
5. 点击“退出登录”，当前会话在 Redis 中删除，页面清除用户与工单。

observer 使用同一个初始密码，可以登录，但没有工单查询权限，查询会显示 403 提示。修改本地 .env 不会自动修改已有 MySQL 账号密码。

页面没有内置密码；密码提交结束后清空，token 只在当前页面内存中，刷新或关闭页面会失去本地登录状态。刷新不等于向服务端退出，遗留会话按 Redis 原定 TTL 过期；需要立即撤销时先点击退出。

## 页面提示

- 401：密码错误或登录失效；已失效会话会清除，重新登录即可。
- 403：当前账号无查询权限，登录状态仍保留。
- 404：未找到工单，旧结果被清除。
- 429：等待按钮倒计时结束后再试，登录与工单分别计时；限制仍由服务端决定。
- 服务不可用或网络错误：显示重试提示。退出失败时保留登录，允许重试，不能把失败说成已经退出。

请求信息只展示方法、路径、状态、耗时及 TraceId，不展示 token、密码或完整认证响应。登录会先请求 /login 再请求 /me，因此成功登录后通常显示 /me 的信息。耗时是浏览器发起请求至读取响应的总时间，与网关日志耗时不同。

## 文件和启动

frontend/index.html 是页面结构，styles.css 是桌面和窄屏样式，app.js 管理交互及 API 调用。它们挂载到 Nginx 静态目录，不需要 Node 服务或前端编译。

页面通过同源 /api 请求沿原有两层网关进入中台；新增页面后仍是 8 个容器。未知路径仍返回 404，没有把错误地址全部转成首页。

```powershell
pwsh.exe -NoProfile -File .\scripts\start.ps1 -SkipBuild
pwsh.exe -NoProfile -File .\scripts\verify-ui.ps1
```

只改 frontend 文件时通常刷新即可看到更新；浏览器有旧缓存时强制刷新。修改 Nginx 配置后需校验并重载，或重新执行启动脚本。

## 本次验收证据

已用真实 Chrome 验证：错误密码、demo 登录、实际 MySQL 工单、404、编号校验、TraceId 复制、observer 的 403、服务端撤销会话后的 401、退出、刷新清除内存登录。1360 像素桌面与 390 像素窄屏截图已检查，窄屏无横向溢出。

浏览器拦截响应验证：登录及查询的 429 倒计时、网络中断、退出 503 保留会话，以及工单标题作为纯文本显示。此处 429 是页面状态模拟；后端实际限流证据见限流学习与操作.md 和搭建日志。

scripts/verify-browser.cjs 是浏览器验收脚本，需 Node、Chrome 和已安装的 Playwright 库；通过 PLAYWRIGHT_MODULE 指定库目录。本机已执行，不是页面运行依赖。脚本只输出脱敏结果，结束时撤销自己的会话。截图位于 output/playwright，测试产物不纳入源码提交。
