# 第一阶段实施方案

## 目标和边界
复现已经确认的请求链路：Nginx → 应用层网关 → 应用层服务 → 中台网关 → 中台服务 → MySQL。由助手直接搭建；每一步更新《搭建日志.md》。这一阶段不加入 Redis、Kafka、业务鉴权、限流、完整 TraceId 或 Kubernetes。

## 架构
四个独立 Java 进程，两个网关使用 Spring Cloud Gateway，两个业务服务使用 Spring MVC。网关通过 Nacos 发现同层服务。Nacos 使用 application、platform 两个命名空间；应用层通过 PLATFORM_GATEWAY_URL=http://platform-gateway:8080 跨层调用。这里的主机名由 Docker DNS 解析，不是 Nacos 跨命名空间发现。

MySQL 初始化 tickets 表及 id=1 的示例工单；GET /api/tickets/1 沿完整链路查询。不存在记录返回 404，非数字 ID 返回 400，中台连接失败返回 502，超时返回 504。各层输出普通请求日志；网关和业务服务添加演示响应头，验证每一跳。完整分布式追踪留待后续。

## 部署和资源
使用 Compose 项目名 novacloud-lab 隔离本实验；仅入口、Nacos 控制台和数据库映射到 127.0.0.1。数据库及 Nacos 数据使用命名卷，正常 down 不删除。镜像构建在 Docker 中完成，不改变本机 JDK 8。Nacos 单机模式且关闭鉴权，仅供本地实验。

## 验收
入口 GET /api/tickets/1 返回数据库中的 id、title、status；响应含 X-Lab-Nginx、X-Lab-App-Gateway、X-Lab-App-Service、X-Lab-Platform-Gateway、X-Lab-Platform-Service。两个命名空间各有对应网关和服务，且实例健康。Docker Compose 服务健康；单元/接口测试与完整链路验收通过。
