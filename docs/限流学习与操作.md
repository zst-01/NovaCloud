# 登录与工单限流

## 当前规则

| 对象 | 默认额度 | 依据 |
| --- | --- | --- |
| POST /api/auth/login | 30 秒 10 次 | Nginx 看到的来源 IP；成功、失败都占额度 |
| /api/tickets/** | 10 秒 20 次 | 服务端会话中的用户名；同账号不同 token 共用额度 |

限流只在应用层网关扣额。无有效身份或权限的工单请求先返回 401 / 403；个人信息、退出和健康检查不消耗额度。

超额返回 HTTP 429，正文如 `{"error":"rate_limited","retryAfter":7}`，响应头 `Retry-After: 7` 表示约 7 秒后重试。响应仍有 X-Trace-Id，完成日志只存在于 Nginx 和应用网关。

## 验收

在项目目录的 PowerShell 7 运行：

```powershell
pwsh.exe -NoProfile -File .\scripts\verify-rate.ps1
# 可选：短暂停止 Redis 并自动恢复，验证限流故障响应。
pwsh.exe -NoProfile -File .\scripts\verify-rate.ps1 -IncludeFailure
```

脚本验证登录超额、伪造 IP 头、并发、同账号两个 token 共享额度、特殊路径及过期恢复，通常约一分钟。实验会占用本机来源和 demo 的额度，请暂停其他同来源登录和 demo 查询，以免计数互相影响。脚本清理自己的会话，计数自然过期，不清空 Redis。

start.ps1 会自动运行常规限流验收。其他功能验收遇到 429 会按 Retry-After 等待，最多尝试三次；限流专项脚本直接观察响应，不自动重试。

## Redis 如何计数

首次请求创建计数 1 并设置 TTL，窗口内继续累加，到达上限就拒绝，拒绝不延长窗口。key 过期后下一个请求开始新窗口。

检查、增加和设置过期时间在一段 Redis Lua 中原子完成，多实例共享同一 Redis 额度。key 为 `lab:rate:login:<身份SHA256>` 或 `lab:rate:tickets:<身份SHA256>`，不使用 token；哈希减少直接暴露身份，不等于加密或匿名化。

这是固定窗口，窗口交界处仍可能短时突发，不是滑动窗口或令牌桶。Redis 故障时登录返回 503 / rate_limit_unavailable；已登录查询可能在更早的会话校验阶段返回 503 / session_unavailable，均不会自动放行。

## IP 信任边界

Nginx 将 X-Lab-Client-IP 覆盖为 `$remote_addr`，外部调用者修改该头或 X-Forwarded-For 不会获得新额度。Docker Desktop、NAT 或代理可能让不同用户显示为同一 IP，他们会共享登录额度。

应用网关没有宿主机端口，仅在当前受信任的 Docker 内网接受入口来源头。能够伪造内网流量的容器不在这个保证内。添加其他入口、开放网关端口或跨主机部署时，应重新配置受信任代理边界。

## 代码与配置

- app-gateway/src/main/resources/application.yml：lab.rate 阈值和窗口秒数，必须为正数；登录、工单、其他认证路由分开配置。
- RateLimitFilter：按实际匹配路由执行，读取已验证用户名，返回 429 或 503。
- SessionAuth：把会话用户名放进请求属性，不读取客户端身份头。
- RedisWindowLimiter / rate-window.lua：响应式 Redis 调用与原子计数。
- infra/nginx/nginx.conf：覆盖来源头。
- scripts/verify-rate.ps1：实际 HTTP 验收。

修改配置后运行完整 start.ps1 重新构建。限流验收默认检查 10 次登录和 20 次工单额度；修改额度后可给脚本传 -LoginLimit、-TicketLimit，并同步启动脚本调用。阈值只供本机学习，不代表生产容量。Kafka 本阶段未接入。

当前验收脚本接受 60 秒以内的 Retry-After；配置更长窗口时需要同步调整验收等待上限。登录策略按来源计数，没有实现账号锁定或跨多个来源的账号攻击检测。
