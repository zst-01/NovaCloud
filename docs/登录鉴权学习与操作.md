# 登录、退出与权限：运行和学习入口

## 先实际调用

当前工单接口必须登录。直接用浏览器打开 `/api/tickets/1` 得到 401 是预期行为，尚未制作登录页面。在项目目录打开 PowerShell 7：

```powershell
. .\scripts\auth-session.ps1
$headers = New-LabSession
Invoke-RestMethod http://127.0.0.1:18080/api/auth/me -Headers $headers
Invoke-RestMethod http://127.0.0.1:18080/api/tickets/1 -Headers $headers
Remove-LabSession -Headers $headers
```

辅助脚本读取本地 `.env` 的 DEMO_PASSWORD，以 demo 账号登录，把 token 留在变量中，不输出凭据。退出后再次查询返回 401。在 API 工具中可以手动 POST `/api/auth/login`，JSON 字段为 username、password；把响应 token 放进后续请求头 `Authorization: Bearer <token>`。不要把真实密码或 token 贴到聊天、截图或日志。

两个初始账号：demo 有 ticket:read 权限；observer 可以登录和查询自身信息，但查询工单返回 403。两者初始密码均来自 DEMO_PASSWORD。MySQL `lab_users` 只保存 BCrypt 哈希。启动时仅补充不存在的账号，因此修改 `.env` 不会修改已存在账号的密码。

完整验收：

```powershell
pwsh.exe -NoProfile -File .\scripts\verify-auth.ps1
# 可选：短暂停止本项目 Redis，检查故障时拒绝请求，然后自动恢复。
pwsh.exe -NoProfile -File .\scripts\verify-auth.ps1 -IncludeFailure
```

原来的 verify.ps1、verify-trace.ps1、verify-failure.ps1 已自动加入登录及测试会话清理。start.ps1 会自动执行常规登录鉴权验收。

## 请求中的分工

登录请求依次经过 Nginx、应用网关、应用服务、中台网关、中台服务。中台查 MySQL 并验证密码，生成随机 token，把用户和权限写入 Redis，固定有效期 1800 秒。应用服务仍按真实项目背景承担转发。

后续请求携带 token。两层网关各自查 Redis，中台服务也检查会话；应用服务通过 RestClient 透传 Authorization。各层不信任客户端填写的用户 ID 或角色头。网关使用响应式 Redis API，中台 Servlet 服务使用同步 API。它们访问同一个 Redis，这是当前本地示例的设计，并不代表每种公司架构都必须共享会话库。

默认先校验会话，只精确放行登录和所需健康检查路径。当前除个人信息、退出之外的业务请求要求 ticket:read；新增业务接口时应明确配置其权限规则。未知网关路径在匿名时返回 401，demo 登录后才返回 404。

| 响应 | 含义 |
| --- | --- |
| 200 | 登录、查询或退出成功 |
| 400 | 登录字段不合法；已登录但工单 ID 格式错误 |
| 401 | 密码错误，或 token 缺失、无效、过期、已退出 |
| 403 | 已登录但没有工单查询权限 |
| 503 | Redis/认证存储不可用；不允许绕过校验 |

这次使用随机 token + 服务端会话，没有使用 JWT。Redis key 为 `lab:session:<token>`，值只保存用户名和权限，不保存密码。退出删除当前 key；固定 TTL 不因访问延长。过期实验只把测试脚本自己的新会话缩短为 1 秒，不影响其他会话。

## 日志和代码

登录、退出和被拒绝请求也返回 X-Trace-Id；使用 show-trace.ps1 查询。被应用网关拒绝的请求只经过 Nginx 和应用网关，不会出现后续业务层日志。请求日志不记录 Authorization 和登录正文。

- 中台 DemoUsers：建表、补充演示账号、BCrypt 校验。
- 中台 AuthController / SessionStore：登录、个人信息、退出和 Redis 会话。
- 中台 SessionFilter：服务入口检查，防止直接调用绕过网关。
- 两层网关 SessionAuth：非阻塞会话和权限校验。这两个独立模块目前各保留同一份小型策略，后续修改时应同步测试两者。
- 应用层 AuthProxy / PlatformClient：固定 URL 转发及请求头透传。

## 当前边界

已实现的是本机演示接口权限，没有登录页面、注册、密码修改、完整 RBAC 后台、登录限流、HTTPS、SSO 或刷新 token。权限是登录时快照；修改数据库权限后需退出重登。退出只撤销当前 token，已开始处理的请求不保证被撤销。Kafka 及 Kubernetes 仍待后续阶段。
